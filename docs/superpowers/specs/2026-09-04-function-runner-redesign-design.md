# 座標射擊 Function Runner 重新設計

日期：2026-09-04
狀態：設計已確認，待實作

## 目標

把「調係數讓曲線通過目標點」改成「自己寫函式射擊」：畫面左側有出發點，玩家輸入 f(x)，曲線從出發點往右畫，經過目標點就消滅、撞到障礙物就停下並炸開一小塊。每題射擊次數固定，難度越高目標越多、次數增加得越少。另加同一台裝置上的雙人對戰。

不做的事：線上對戰、電腦對手、即時預覽曲線。

## 名詞

- **棋盤 board**：以座標單位描述的矩形，`{ minX, maxX, minY, maxY, cell }`，`cell = 0.5`。
- **格 cell**：障礙物以 0.5 單位的方格存放，索引 `row * cols + col`，`col = floor((x - minX) / cell)`，`row = floor((y - minY) / cell)`。
- **出發點 shooter**：`{ x, y, dir }`，`dir` 為 +1（朝右）或 −1（朝左）。
- **目標 target**：`{ id, x, y }`，命中半徑 0.4。
- **射擊 shot**：一次以 f 為函式的曲線追蹤，結果見「射擊模擬」。

## 單人模式規則

### 棋盤與出發點

- 棋盤 x ∈ [0, 20]、y ∈ [−8, 8]，40 × 32 格。
- 出發點固定在原點 (0, 0)，`dir = +1`。
- 格線每 1 單位一條，x 軸（y = 0）與左緣較亮；每 2 單位標一個整數座標。

### 函式與曲線

- 玩家輸入 f(x)，實際畫出的曲線是 `y = f(x) − f(0)`，因此曲線一定從出發點畫起。規則文字會說明「常數項會被抵銷」。
- 若 `f(0)` 不是有限數（例如 `ln(x)`、`1/x`），這次射擊無效、不消耗次數，輸入列顯示「f(0) 沒有定義，曲線無法從出發點畫起」。
- 語法錯誤同樣不消耗次數，輸入列顯示錯誤訊息並標紅。

### 射擊模擬

`simulateShot(board, obstacles, targets, shooter, f)` 是純函式，不修改輸入，回傳：

```
{
  path: Point[]          // 畫出的折線（絕對座標）
  hits: string[]         // 依序被打中的目標 id
  impact: Point | null   // 撞到障礙物的位置
  cleared: number[]      // 要清除的格索引
  end: "edge" | "top" | "bottom" | "obstacle" | "undefined"
}
```

追蹤方式：

1. 令 `t` 從 0 起每步增加 0.02，直到超出棋盤右緣（或左緣，依 `dir`）。第 i 點為 `(shooter.x + dir · t, shooter.y + f(t) − f(0))`。
2. 若下一點的 y 不是有限數，射擊在上一點結束，`end = "undefined"`。
3. 若下一點的 y 超出 [minY, maxY]，用線性內插把最後一段截到邊界，檢查完這一段後結束，`end = "top"` 或 `"bottom"`。
4. 每一段（上一點到下一點）先檢查障礙物：沿線段以不超過 0.125 的間距取樣，第一個落在已佔用格內的取樣點就是撞擊點；曲線在撞擊點結束，`end = "obstacle"`，`cleared` 為格中心與撞擊點距離 ≤ 1.1 的所有已佔用格。
5. 再檢查目標：目標中心到這一段（若撞到障礙物則到撞擊點為止）的距離 ≤ 0.4 即命中，加入 `hits`（每個目標只記一次）。曲線穿過目標後繼續前進，一發可以連中多個。
6. 走到棋盤左右邊界結束，`end = "edge"`。

不連續的函式（例如 `floor(x)`）相鄰取樣點之間仍以直線相連，所以跳躍會變成一段垂直線，同樣會撞障礙物、也能命中目標，不能用跳躍穿牆。

### 進行與勝負

- 遊戲狀態：`{ puzzle, alive: Set<targetId>, obstacles: Set<cellIndex>, shotsUsed, shots: ShotResult[] }`。
- `fireSolo(state, expression)` 回傳新的狀態與這次的 `ShotResult`；解析失敗或 `f(0)` 無定義時回傳錯誤、狀態不變。
- 全部目標消滅即過關，顯示用了幾發。
- 次數用完仍有目標即失敗，可「重來這題」（同一題、障礙物復原）或「新題目」。
- 每日挑戰固定「困難」，種子為 `${seed}:function-runner:hard`，過關時 emit `solved`；失敗只提供重來，重來拿到同一題。

### 難度

| 難度 | 目標 | 射擊次數 | 障礙物 | 隱藏曲線的目標分組 |
| --- | --- | --- | --- | --- |
| 簡單 easy | 3 | 3 | 0 | 1, 1, 1 |
| 普通 normal | 5 | 4 | 2 | 2, 2, 1 |
| 困難 hard | 7 | 4 | 4 | 3, 2, 2 |
| 專家 expert | 10 | 5 | 6 | 3, 3, 2, 2 |

### 產生器與可解性保證

`generateFunctionRunnerPuzzle(rng, difficulty)` 從答案反推題目，所以每題保證在次數內可解，並把隱藏曲線的算式字串一起回傳（`solution: string[]`），測試會拿它實際跑一遍解析與射擊模擬。

隱藏曲線家族（都以 `f(x) − f(0)` 的形式通過原點，參數讓整數 x 對應整數 y）：

| 家族 | 形式 | 參數 | 可用的 x | 算式範例 |
| --- | --- | --- | --- | --- |
| 直線 | `m·x` | m = p/q，q ∈ {1, 2, 3}，p ∈ [−3, 3] 去 0，且 \|m\| ≤ 2 | q 的倍數 | `2x`、`-x/2`、`2x/3` |
| 拋物線 | `a·x² + b·x` | a ∈ {±¼, ±½, ±1}，b ∈ [−3, 3] | a 為 ±¼、±½ 時 x 為偶數，否則任意 | `x^2/4 - 3x`、`-x^2/2 + 2x` |
| 正弦 | `A·sin(2πx / p)` | A ∈ [2, 6]，p ∈ {4, 8, 12} | p/4 的奇數倍（波峰波谷，y = ±A）與 p/2 的倍數（y = 0） | `3sin(pi x/2)`、`4sin(pi x/4)`、`2sin(pi x/6)` |
| V 形 | `a·\|x − c\|` | a ∈ {±½, ±1}，c ∈ [3, 10] | a 為 ±½ 時 x 為偶數，否則任意 | `abs(x-5)`、`-abs(x-6)/2` |

分組規則：1 個目標的組只用直線；2 個目標的組用直線或拋物線；3 個目標的組用直線、拋物線、正弦或 V 形。

目標放置：

- x 為 [2, 19] 的整數，y 為 [−7, 7] 的整數。
- 任兩個目標的距離 ≥ 1.5（整數座標下即不相鄰、不斜鄰）。
- 每組先隨機選家族與參數，算出符合條件的 x，數量不足就重選；再隨機取該組需要的 x，檢查間距，失敗就重選（每組最多 200 次，仍失敗則整題重新產生）。
- 每組最遠的目標 x ≥ 6，且 2 個以上目標的組橫跨至少 3 欄，避免目標全擠在出發點旁邊、右半邊與障礙物都派不上用場。
- 隱藏曲線從出發點到該組最遠目標之間的路徑（以 0.05 取樣成折線）必須全程留在 y ∈ [−7.5, 7.5] 內，否則射擊會在中途離開畫面而打不到後面的目標。

障礙物放置（每個最多 200 次嘗試；放不滿就整題重新產生，所以障礙物數量永遠等於難度表的數字）：

- 形狀二選一：圓形（半徑 0.8 到 1.5）或直立牆（寬 1，高 2 到 4），中心 x ∈ [3, 18]、y ∈ [−7, 7]，格中心落在形狀內的格即被佔用。
- 不得與既有障礙物重疊；每個格中心與出發點距離 ≥ 2、與任一目標距離 ≥ 1、與任一隱藏路徑折線的距離（點到線段）≥ 0.75。距離量到線段而不是取樣點，因為陡峭的曲線相鄰兩個取樣點可以差好幾個單位。

測試會驗證：幾百個種子與 2025 到 2027 每一天的每日挑戰，依序射出 `solution` 裡的算式後目標全部消滅、用掉的次數 ≤ 射擊次數、途中不撞障礙物。

## 雙人模式規則

- 棋盤 x ∈ [−10, 10]、y ∈ [−8, 8]。玩家一 3 個單位在 x ∈ [−9, −6]，玩家二 3 個在 x ∈ [6, 9]，y 為 [−6, 6] 的整數，任兩單位距離 ≥ 2。障礙物 5 個（形狀同單人）置於 x ∈ [−4, 4]，格中心與任一單位距離 ≥ 1.5。每局以 `Date.now()` 為種子。
- 玩家一先手，輪流射擊。輪到的玩家點自己的一個存活單位當出發點（預設自動選上次之後的下一個），輸入 f(x) 發射。玩家一 `dir = +1`，玩家二 `dir = −1`，所以兩邊都是「朝對手方向為 +x」。
- 目標只有對方的存活單位：曲線經過（距離 ≤ 0.4）就消滅；穿過自己的單位不受影響。障礙物一樣停下並炸出缺口，缺口會留到下一回合。
- 沒有次數限制。對方單位清光即獲勝，顯示「玩家一獲勝」或「玩家二獲勝」，可再來一局（重新產生地圖）。
- 狀態：`{ board, units: PvpUnit[], obstacles: Set<number>, turn: 1 | 2, winner: 0 | 1 | 2, shots: ShotResult[] }`，`firePvp(match, unitId, expression)` 檢查該單位屬於當前玩家且存活，回傳新的對局與結果。

## 函式語法

`app/utils/expression.ts` 提供 `compileExpression(source)`：

- 成功回傳 `{ ok: true, f: (x: number) => number }`，失敗回傳 `{ ok: false, error: string, position: number }`，錯誤訊息為中文（例如「括號沒有配對」「不認識的名稱 y」「這裡少了數字」）。
- 數字：整數與小數。常數：`pi`、`e`。變數：`x`。
- 運算子：`+ − * /`、`^`（右結合，`2^3^2 = 512`）、一元負號（`-x^2 = -(x^2)`）、括號。
- 隱含乘法：數字、`x`、常數或右括號後面接 `x`、數字、名稱或左括號時視為相乘，例如 `2x`、`3(x+1)`、`(x+1)(x-1)`、`2sin(x)`、`pi x`。
- 函式（必須加括號）：`sin cos tan abs sqrt exp ln log floor`，`log` 與 `ln` 都是自然對數。
- 定義域外的值照 JavaScript 規則回傳 `NaN` 或 ±∞，由射擊模擬當成「離開畫面」處理。
- 不用 `eval` 或 `new Function`。

## 介面

沿用現有遊戲外殼（`GameTopbar`、`.hud` / `.chip`、`.board-wrap` + `.overlay`、`aside.panel`）。

- **頂欄**：單人「新題目」（每日：「重來」），雙人「再來一局」。
- **HUD**：單人「目標 剩餘/總數」「射擊 剩餘/總數」「難度」；雙人「玩家一 存活數」「玩家二 存活數」「回合 玩家一/二」。
- **棋盤**：SVG，每單位 50 px，繪圖區 1000 × 800，外加座標標籤的邊距。內容：格線與標籤、障礙物（單一 `<path>`，`shape-rendering: crispEdges`）、目標（半徑 0.4 單位的圓，旁邊小字座標 `(x, y)`）、出發點（實心圓）、雙人的單位（玩家一實心、玩家二空心，同一個 accent 色；輪到的單位有外圈）、本題的歷史射線（淡）、正在畫的射線（亮）。
- **輸入列**（棋盤下方）：`f(x) =` 標籤、單行文字輸入（等寬、關閉自動校正）、「發射」鈕；Enter 也能發射。雙人時標籤前面多一句出發點與方向，例如「從 (−8, 2) 朝右」，而且每個單位旁邊都標絕對座標，玩家自己換算相對位移。下方一排快捷鍵：`x ^ ( ) sin cos abs sqrt`，插入到游標位置。錯誤訊息顯示在輸入列下方。
- **射擊動畫**：折線以 `stroke-dasharray` / `stroke-dashoffset` 依 25 單位/秒畫出（最長約 0.9 秒），畫完才結算命中、清除格子、更新狀態；動畫期間停用輸入與發射。`prefers-reduced-motion` 時直接顯示結果。動畫用 `requestAnimationFrame` 推進，但分頁隱藏時瀏覽器會暫停它，所以另外用計時器在預定時間結算，確保狀態不會卡在「射擊中」。
- **結束遮罩**：單人過關「全部命中」＋「用了 N 發」＋「下一題」（每日：「完成」停用）；單人失敗「次數用完」＋「還剩 N 個目標」＋「重來這題」「新題目」（每日只有「重來」）；雙人「玩家一獲勝」＋「再來一局」。
- **側欄**：「模式」單人／雙人切換（每日隱藏）；「難度」四段（單人且非每日才顯示）；「玩法」兩到三行；「語法」六行左右的對照（`2x+1`、`x^2/4`、`3sin(x)`、`abs(x-5)`、`sqrt(x)`、`e^x`）。不放小技巧或說明以外的文字。

## 測試

- 運算式：優先順序、`^` 右結合、一元負號、隱含乘法、各函式、常數、錯誤（括號不配對、未知名稱、空字串、多餘符號、函式沒括號）、`NaN` 與 ±∞ 的傳遞。
- 射擊模擬（手工棋盤）：直線命中多個目標、撞牆停下並炸出正確的格、曲線離開上下緣、`f(0)` 無定義、跳躍函式不穿牆、不修改輸入。
- 產生器：每個難度的數量、整數座標、間距、目標不在障礙物內、出發點附近淨空、同種子相同、不同種子不同。
- 可解性：幾百個種子與三年份每日挑戰，`solution` 依序射出後全部命中。
- 雙人：地圖合法、只能用自己的存活單位、命中對方單位、穿過自己的單位、輪流、勝負判定、缺口保留。
